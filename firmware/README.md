# STM32 Firmware

This directory will contain the firmware for the STM32F746G-DISCO board
(MCU: STM32F746NGH6). See `docs/hardware.md`.

## Current state

The STM32CubeMX project lives in `STM32AudioController/` (CMake project
type, STM32F746G-DISCO board preset). Build instructions, presets and
tool versions are in `docs/toolchain.md`.

```text
cd firmware/STM32AudioController
cmake --preset Debug
cmake --build --preset Debug
```

Use the STM32Cube bundle CMake 4.4.0 (PATH setup, flashing, VCP log and
framebuffer dump: `docs/toolchain.md`). Hardware status: see the
bring-up log in `docs/hardware.md`.

At boot `App_Main()` initialises the SDRAM, runs a self-test and draws
an LCD test pattern (`App/Src/sdram.c`, `App/Src/lcd_test.c`), logging
each step on the ST-LINK VCP (`docs/firmware-log.md`).

## UI and simulator

The touch UI is written against LVGL only, in `firmware/ui/` (see its
README). `firmware/simulator/` builds it on Linux and renders the screens
to PNG without a board: `tools/run-ui-simulator.sh`. LVGL v9.5.0 is a git
submodule; run `git submodule update --init` after cloning, otherwise the
firmware build stops with "LVGL not found".

On the board (`App/Src/ui_port.c`) LVGL draws into two framebuffers in
SDRAM (`0xC0000000`, `0xC0040000`) and the LTDC switches between them
during vertical blanking; the FT5336 is the LVGL pointer input. Until
The UI is fed by the PC over USB: `App/Src/usb_link.c` is the vendor HID
interface (ADR-003) and `App/Src/link_port.c` connects it, through the
portable protocol client in `firmware/link/`, to the UI. Without a PC the
UI shows the waiting screen. `App/Src/ui_demo.c` (option `APP_UI_DEMO`)
feeds a fixed device list instead, to try the UI without a PC.

Build options (CMake cache variables):

| Option | Default | Effect |
|---|---|---|
| `APP_TEST_SCREEN` | `OFF` | `ON`: show the M1 test pattern and touch targets instead of the UI (needed for the framebuffer `--expected` check in `docs/toolchain.md`) |
| `APP_UI_DEMO` | `OFF` | `ON`: demo device list instead of the USB host link |

```text
cmake --preset Debug -DAPP_TEST_SCREEN=ON
```

## Layout

```text
firmware/
├── ui/                   # LVGL UI, hardware independent (+ lv_conf.h, fonts)
├── link/                 # protocol client (STM32 side), hardware independent, tests
├── simulator/            # headless Linux build of ui/ for screenshots
firmware/STM32AudioController/
├── App/                  # hand-written application code (never generated)
│   ├── Inc/
│   └── Src/
├── Core/                 # CubeMX generated (edit only inside USER CODE)
├── Drivers/              # CubeMX copy of HAL / CMSIS
├── Middlewares/          # CubeMX copy of FreeRTOS, USB Device lib;
│                         # Third_Party/lvgl is the LVGL submodule
├── FATFS/ USB_DEVICE/    # CubeMX generated
├── cmake/                # CubeMX generated toolchain + source lists
├── CMakeLists.txt        # generated once; user sections maintained by us
├── CMakePresets.json
└── STM32AudioController.ioc
```

Rules:

- New firmware code goes in `App/`. Add each source file explicitly to
  `target_sources` in `CMakeLists.txt` (no globbing); `App/Inc` is
  already on the include path.
- Generated code calls the application only from CubeMX `USER CODE`
  sections. Today the single hook is `App_Main()`, called from
  `StartDefaultTask` in `Core/Src/freertos.c`.
- `cmake/stm32cubemx/CMakeLists.txt` is regenerated by CubeMX; do not
  edit it by hand.

The enabled peripheral set is defined in
`docs/decisions/ADR-001-firmware-peripheral-set.md`.

## Planned components

- STM32Cube-generated startup/peripheral code
- application layer
- LVGL UI
- touch handling
- USB HID transport
- shared protocol adapter

The board model has been verified (see `docs/hardware.md`). The CubeMX
project should use the STM32F746G-DISCO board configuration, with GPIO and
peripheral assignments taken from the official ST documentation and
STM32CubeF7 BSP rather than guessed.
