# Firmware

## Layout

```text
firmware/
├── STM32AudioController/     STM32CubeMX project (CMake)
│   ├── App/                  hand-written code (never generated)
│   ├── Core/ USB_DEVICE/     generated; edited only inside USER CODE
│   └── Middlewares/…/lvgl    LVGL v9.5.0 (git submodule)
├── ui/                       LVGL screens, hardware independent
├── link/                     protocol client (STM32 side), with tests
└── simulator/                headless Linux build of ui/ → PNG
```

| File | Role |
|---|---|
| `App/Src/app.c` | `App_Main()`: clock check, SDRAM, touch, then the UI or the test screen |
| `App/Src/usb_link.c` | Vendor HID class; the ISR copies frames into a 40-frame static queue |
| `App/Src/link_port.c` | USB state → link client → UI, every UI loop |
| `App/Src/ui_port.c` | LVGL display (two SDRAM framebuffers) and touch input |
| `App/Src/ui_demo.c` | Fixed device list for `APP_UI_DEMO` |
| `App/Src/touch.c` | FT5336 driver (I²C3, polling) |
| `App/Src/clock_check.c` | Measures the TIM5 clock against the LSE crystal |
| `App/Src/sdram.c`, `lcd_test.c` | SDRAM init and self-test, M1 test pattern |

Generated code calls the application from two USER CODE hooks:
`App_Main()` in `StartDefaultTask` and `UsbLink_DeviceInit()` in
`USB_DEVICE_Init_PreTreatment` (ADR-003).

## UI

- Four device buttons per page (2×2) with icon and name; arrows when
  there are more than four devices.
- Active device: colour and text. Tapped device: "pending" until the host
  confirms.
- Bottom strip: mute button, volume slider with percentage, page arrows.
  Disabled while the volume is unknown; volume changes are sent at most
  every 100 ms while dragging.
- Flip button (top right, hold 1 s): turns the image and touch by 180°
  for a board mounted upside down.
- Without a host: a waiting screen. Notices when the host refuses a
  selection or does not answer within 2 s.
- Text is Turkish; fonts (Montserrat with Turkish letters, Font Awesome
  icons) are generated by `tools/gen-ui-fonts.sh`.

## Protocol client (`firmware/link`)

- On USB connect: sends `GET_DEVICE_LIST`, repeats every 1 s until a
  complete list has arrived.
- Shows a list only when all its entries are there; asks again if a new
  list stays incomplete for 1 s.
- `SELECT_DEVICE` without an answer in 2 s: "host not responding",
  waiting screen, list requested again.
- Answers malformed frames with `ERROR`, never an `ERROR` frame.

## Build options

| CMake option | Effect |
|---|---|
| (none) | UI fed by the PC over USB |
| `APP_TEST_SCREEN=ON` | M1 test pattern, five touch targets, dot under the finger |
| `APP_UI_DEMO=ON` | UI with demo devices, no PC |

## Log lines

Selected lines (all of them: [firmware-log.md](https://github.com/egungor/stm32-audio-controller/blob/main/docs/firmware-log.md)),
USART1 at 115200 8N1 on the ST-LINK virtual COM port:

| Line | Meaning |
|---|---|
| `BOOT OK sysclk=200000000` | Default task started |
| `CLOCK MEASURE PASS ref=LSE tim=… exp=… ppm=…` | Clock within ±500 ppm of expected |
| `SDRAM INIT OK`, `SELFTEST SDRAM PASS size=8388608 ms=…` | SDRAM usable |
| `TOUCH INIT OK id=0x51` | FT5336 found |
| `UI INIT OK fb0=0xC0000000 fb1=0xC0040000` | LVGL running |
| `UI FLIP on\|off copy_max_ms=…` | Image turned by 180° or back |
| `APP READY` | Main loop running |
| `USB CONFIGURED` / `USB DISCONNECTED` | PC link up / down |
| `LINK LIST OK n=… gen=…` | Device list received and shown |
| `LINK ACTIVE id=…` | Host reported a new default |
| `UI SELECT id=…` | User tapped a device |
| `LINK SELECT FAIL reason=host_error\|timeout` | Selection refused or not answered |

## Memory

Release build, Linux toolchain: about 334 KB flash and 112 KB static RAM
(of 1 MB and 320 KB). Framebuffers are in SDRAM; the LVGL heap is a 64 KB
static array in internal RAM.
